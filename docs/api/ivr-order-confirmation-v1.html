IVR Order Confirmation — Internal/Admin API (Target V1 Draft) (1.0.0-draft.32)

Download OpenAPI specification:

License: LicenseRef-Proprietary

Target V1 draft for the standalone .NET IVR service. Not a public API. The Sales Platform owns business call selection, eligibility, revalidation, and order-state transitions. A task accepted by IVR is a call instruction already selected by M3; IVR may still hold or reject it only at contract, authorization, safety, privacy, timing, or capacity gates. Supports GOLDEN_HOUR+ONLINE and TWENTY_FOUR_SEVEN+COD. External Sales callback is specified separately in order-core-ivr-callback.target-v1.yaml.

Append-only audit trail for one object, with mandatory reason (perm IVR_QUEUE_VIEW)

Returns the audit rows recorded against a single target_type/target_id, newest first. Both selectors are required: a call with neither would be a bulk extract of the trail wearing the clothes of a lookup, so the absence of a filter is refused rather than defaulted to "everything". reason is mandatory and the read writes its own audit row, whose id comes back as access_audit_id. Reading an audit trail is the access most worth recording, so the response hands back the id of its own entry rather than leaving the caller to go looking for it. truncated says whether the store held more than limit rows. It is a field rather than something the caller infers from rows.length == limit, because that inference is wrong exactly when the count lands on the limit by coincidence, and an auditor who believes they have the whole trail when they do not is worse off than one who knows they do not. This is a GET because it is a read that is audited, not a state change. The underlying table refuses UPDATE and DELETE at the database (trg_ivr_audit_log_append_only), so no caller of this API can alter what it returns.
